# ADR 0001: Python 단일 서비스로 구성한다

이 문서는 RuleCite의 서버 구성 결정을 기록한다. 서비스 구조를 바꾸거나 Spring Boot 분리를 다시 검토할 때 읽는다.

- 상태: 채택
- 날짜: 2026-11-04

## 결정

인증, 역할, 문서 관리, 인덱싱, 검색, 답변 생성을 FastAPI 서버 하나(`server/`)에서 처리한다.
서버 안은 `auth`, `documents`, `worker`, `rag` 모듈로 나눈다.
슬랙 봇(`bot/`)은 별도 프로세스로 둔다.

## 배경

초안은 업무 로직을 Spring Boot(`api/`)에, AI 처리를 FastAPI(`rag/`)에 두었다.
분리한 이유는 두 언어 경험을 보여주기 위해서였다.
두 언어를 모두 써야 한다는 요구사항은 없다.

서비스를 나누면 다음 문제를 따로 풀어야 한다.

- 두 서비스가 같은 DB에 접근하므로, 스키마와 마이그레이션을 어느 쪽이 맡을지 정해야 한다.
- API가 RAG 서비스에 인덱싱 작업을 넘기는 방식을 정해야 한다.
- 로드맵 3단계(Spring Boot 연동, 1~2주)가 전체 4~6주 중 가장 길지만, 평가 지표는 개선하지 않는다.

트래픽, 팀 구성, 배포 주기처럼 서비스를 나눌 근거는 이 프로젝트에 없다.

## 검토한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| Spring Boot와 FastAPI로 분리 (초안) | Java 백엔드에 AI 서비스를 붙이는 구성을 보여준다 | 스키마 담당과 서비스 간 작업 전달을 설계해야 한다. 3단계가 1~2주 걸린다 |
| FastAPI 단일 서비스 (채택) | DB를 쓰는 주체가 하나다. 3단계가 1주로 줄어 5단계 성능 개선에 시간을 쓸 수 있다 | Java 경험이 포트폴리오에 드러나지 않는다 |

3단계 1주는 작업 목록을 기준으로 한 추정값이다.

## 결과

- 비동기 인덱싱은 `ingestion_jobs` 테이블을 polling하는 워커로 구현하고, 메시지 큐는 쓰지 않는다.
- 워커를 여러 개 띄우면 같은 작업을 두 번 가져가지 않도록 행 잠금(예: `SELECT ... FOR UPDATE SKIP LOCKED`)을 건다.
- 권한 필터는 그대로 검색 SQL에 건다. 서비스 수는 권한 통제 방식에 영향을 주지 않는다.
- 모듈 사이의 호출은 각 모듈이 공개한 함수로만 한다. 이 경계를 지키면 나중에 `auth`와 `documents`를 별도 서비스로 분리할 수 있다.
- 워커를 서버 프로세스 안에서 돌릴지 별도 프로세스로 띄울지는 로드맵 3단계에서 정한다.
