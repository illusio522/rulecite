# ADR 0003: 개발 DB와 마이그레이션 방식을 정한다

이 문서는 개발용 PostgreSQL의 위치, 앱의 DB 계정, 스키마 변경 방식, 벡터 인덱스 시점을 기록한다.
스키마를 바꾸거나 개발 환경을 새로 준비할 때 읽는다.

- 상태: 채택
- 날짜: 2026-11-05

## 결정

| 항목 | 결정 |
|---|---|
| 개발 DB | `~/Workspace/shared-infra`의 `postgres` 서비스(`pgvector/pgvector:pg17`)를 쓴다 |
| 앱 계정 | 관리자 계정 대신 `rulecite` 전용 계정을 쓴다. 이 계정이 `rulecite` 데이터베이스를 소유한다 |
| 마이그레이션 | `server/migrations/`의 번호 붙인 SQL 파일을 직접 만든 실행기(`rulecite.db.migrate`)로 적용한다 |
| 테이블 범위 | 1단계에는 `documents`, `chunks`만 만든다. 나머지 테이블은 3단계에서 마이그레이션 파일을 추가해 만든다 |
| 벡터 인덱스 | 처음에는 만들지 않고 정확 검색을 쓴다 |
| 접근 등급 일관성 | `chunks`의 `(document_id, access_level)`이 `documents`의 `(id, access_level)`을 외래 키로 참조한다 |

개발 DB 준비 절차는 `scripts/setup-dev-db.sh`에 있다.

## 마이그레이션 방식

| 대안 | 장점 | 단점 |
|---|---|---|
| SQL 파일과 직접 만든 실행기 (채택) | SQL이 그대로 보인다. 권한 조건과 벡터 검색을 SQL로 직접 쓰는 이 프로젝트와 맞고 의존성이 늘지 않는다 | 되돌리기(downgrade)가 없다 |
| Alembic | 표준 도구이고 되돌리기를 지원한다 | 쓰지 않을 ORM(SQLAlchemy)이 함께 들어온다 |

실행기는 `schema_migrations` 테이블에 적용한 파일 이름을 기록하고, 적용하지 않은 파일만 이름 순서대로 파일마다 별도 트랜잭션으로 실행한다.
되돌려야 하면 되돌리는 SQL을 새 번호의 파일로 추가한다.

## 앱 전용 계정

- shared-infra의 관리자 계정은 다른 프로젝트의 DB에도 접근할 수 있다. 앱이 이 계정을 쓰면 앱의 실수가 다른 프로젝트에 영향을 준다.
- pgvector 확장 설치에는 관리자 권한이 필요하므로, `scripts/setup-dev-db.sh`가 관리자 권한으로 한 번 설치한다. 마이그레이션의 `CREATE EXTENSION IF NOT EXISTS vector`는 이미 설치된 경우 아무것도 하지 않는다.
- 비밀번호는 스크립트가 무작위로 만들어 `.env`에만 쓴다.

## 벡터 인덱스를 미루는 이유

- 조각은 1,000개 안팎으로 예상한다. 이 규모에서는 인덱스 없이 전체를 비교하는 정확 검색도 충분히 빠르다.
- HNSW 같은 근사 인덱스는 권한 조건(`WHERE access_level ...`)과 함께 쓰면 요청한 개수보다 적은 결과를 돌려줄 수 있다.
- 정확 검색으로 기준선을 측정하고, 인덱스는 로드맵 5단계에서 전후를 비교하며 추가한다.

## 접근 등급을 외래 키로 묶는 이유

검색 쿼리가 조인 없이 권한 조건을 걸 수 있도록 `chunks`에 접근 등급을 복사해 둔다.
복사한 값이 문서와 어긋나면 권한 위반이 생기므로, 외래 키로 같은 값만 저장되게 한다.
문서의 접근 등급을 바꾸면 `ON UPDATE CASCADE`로 조각의 값도 함께 바뀐다.

## 결과

- 테스트는 실행 중인 개발 DB에 테스트마다 임시 스키마를 만들어 실행하고, 끝나면 지운다. 따라서 테스트 전에 shared-infra의 `postgres`가 실행 중이어야 한다.
- 이 저장소의 `docker-compose.yml`에 있는 `db` 서비스는 로드맵 4단계의 전체 실행 구성에서 정리한다. 이 서비스와 shared-infra의 `postgres`는 같은 5432 포트를 쓰므로 함께 띄우지 않는다.
